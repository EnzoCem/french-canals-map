# EU Waterway Expansion — Design Spec

**Date:** 2026-06-04
**Project:** French Canals → Inland Europe
**Status:** Approved for implementation planning

---

## Overview

Extend the app's coverage from France to 10 countries: France (existing), Belgium, Netherlands, Germany, Switzerland, Austria, Italy, Luxembourg, UK, Ireland. France remains the editorial centre with rich hand-curated data; other countries get OSM-derived bulk coverage with a clear upgrade path to curation.

Delivered in 5 feature-sliced waves, each independently shippable.

---

## 1. Scope & identity

**Countries covered:** FR, BE, NL, DE, CH, AT, IT, LU, UK, IE.

**Branding.**
- Repo name, GitHub Pages URL, `french_canals_map.html` filename, manifest `id` — **unchanged** to preserve existing links and PWA installs.
- In-app title bar: `"French Canals"` → `"Inland Europe"`.
- Updated to match new identity: page `<title>`, meta description, manifest `name` / `short_name` / `description`, README, attribution footer.
- About/help copy explicitly notes France remains the editorial centre.

**Default map view.** Unchanged — opens centred on France. No region picker; users pan/zoom into other countries naturally.

**Localisation.** Out of scope. App remains English-only.

## 2. Data layout

The current monolithic `french_canals_map.html` (~8,200 lines) is extracted: large `const` arrays move to `data/*.json` files loaded via the existing Cache API pattern.

**New file layout:**

```
data/
├── bridges.geojson                    (existing — IENC bridges)
├── ienc_channel_axis.geojson          (existing)
├── ienc_obstructions.geojson          (existing)
├── ienc_locks.geojson                 (existing)
├── ienc_moorings.geojson              (existing)
├── waypoints.json                     (NEW — replaces in-HTML const WAYPOINTS)
├── moorings.json                      (NEW — replaces in-HTML const MOORINGS)
├── routes.json                        (NEW — replaces in-HTML const ROUTES + ROUTE_CONNECTIONS)
├── waterway_constraints.json          (NEW — replaces in-HTML const WATERWAY_CONSTRAINTS)
├── waterway_colors.json               (NEW — replaces in-HTML const WATERWAY_COLORS)
├── tunnels.json                       (NEW — replaces in-HTML const TUNNELS)
├── tidal.json                         (NEW — replaces in-HTML const TIDAL_DATA)
└── closures/                          (NEW — Wave 4)
    ├── fr.json
    ├── nl.json
    ├── de.json
    ├── be.json
    └── at.json
```

`MICHELIN_RESTAURANTS` stays in-HTML (it's regenerated by `fill_michelin.py` and that workflow is already established).

**Schema additions.**

- Every waypoint / mooring entry gains `country: 'FR' | 'BE' | 'NL' | 'DE' | 'CH' | 'AT' | 'IT' | 'LU' | 'UK' | 'IE'` and `source: 'curated' | 'osm'`.
- OSM-sourced entries also get `osm_id` so re-syncs (`fill_osm_pois.py`) preserve user location overrides via stable ID matching.
- `routes.json` entries get `country` and `source`. An entry may span multiple countries (e.g. Rhine: `country: ['CH','FR','DE','NL']`).

**Loading & caching.** All data files served as static JSON, each independently cache-versioned (same constant trick as `WATERWAYS_CACHE_VER`). Service worker precaches them all; bump `VERSION` in `sw.js` once per release wave.

## 3. Wave 1 — Rename + waterway overlay everywhere

Makes the app cover all 10 countries for the basic "where can I sail" question. Mostly a config + extraction change.

**Work items:**

1. **Branding pass.** Title bar, `<title>`, manifest, README, attribution block.
2. **Extract data files** per Section 2. Eight in-HTML consts → `data/*.json` + fetch/cache. App behaviour unchanged.
3. **Extend `fill_waterways.py`.** Widen Overpass bounding box from France to a multi-polygon covering BE/NL/DE/CH/AT/IT/LU/UK/IE. Split into ~20 sub-regions for query time. Same dedup, same RDP simplification (tightened to 40m).
4. **Update `_NON_NAVIGABLE_RE`.** Current pattern is French-only. Add multi-language equivalents: `voorhaven`, `oude` (NL), `alter`, `tunnel`, `wehr` (DE), `disused` (EN). Each new term documented in a code comment with a source link.
5. **`waterway_colors.json` expansion.** ~30 new entries for headline waterways (Rhine, Moselle, Main, Donau, Standing Mast Route, Shannon, Caledonian, Po, etc.). Unmapped waterways fall back to uniform blue.
6. **Cache bumps.** `WATERWAYS_CACHE_VER` → `v8`. `VERSION` in `sw.js` → next.
7. **PWA install test.** Verify the larger waterways file still installs and caches correctly on mobile (iOS Safari, Android Chrome).

**File-size strategy.** Single `waterways.geojson`, RDP at 40m, expected ~50 MB. Per-country splitting and vector tiles considered and deferred — reassess if user-reported slowness emerges.

**Acceptance criteria:**
- App title shows "Inland Europe" on map and PWA install screens.
- Panning to Amsterdam, Berlin, London shows blue canal/river lines, colour-coded where defined.
- Existing France behaviour byte-identical (same colours, same constraints, same overlays).
- PWA installs cleanly; offline mode still works.

## 4. Wave 2 — OSM waypoints + moorings everywhere

Bulk-import OSM data for all 9 new countries. Marked `source: 'osm'` and rendered with a lighter style so curated French markers remain visually dominant.

**New script: `fill_osm_pois.py`.**

```bash
python3 fill_osm_pois.py --countries BE NL DE CH AT IT LU UK IE \
  --out-waypoints data/waypoints.json \
  --out-moorings data/moorings.json
```

- Overpass query per country, batched and rate-limit-aware (template: `fill_waterways.py`).
- **Waypoint candidates:**
  - `waterway=lock_gate` or `lock=yes` → `is_lock: true`
  - `waterway=*` nodes with `name` (canal/river named points)
  - `place=village|town|city` whose centroid is within 500 m of a navigable waterway from `waterways.geojson`
- **Mooring candidates:**
  - `leisure=marina` → `type: 'port'`
  - `mooring=yes|guest|public` → `type: 'halte'`
  - `waterway=fuel` → `type: 'fuel'`
- **Dedup vs existing curated entries.** If an existing curated record is within 200 m AND name-normalised matches, skip. Preserves France.
- **ID scheme:** `w_osm_<osm_id>`, `m_osm_<osm_id>`. No collision with curated `w_NNN` / `m_NNN`.
- **Schema:** `country`, `source: 'osm'`, `osm_id`, plus facilities derived from tags (`capacity`, `electricity`, `water`, `shower`). Empty `desc`.

**Rendering changes** (in `buildMarkers()` / `buildMooringMarkers()`):

- OSM-source markers: 50% opacity, 80% size relative to curated.
- Sidebar metadata row shows a `🅾️ OSM` badge when `source === 'osm'`.
- Sidebar description area shows a "(no curated description — based on OpenStreetMap)" hint with an OSM edit-suggestion link.
- Cluster behaviour unchanged. Vessel-profile filter unchanged.

**Re-sync workflow.** `fill_osm_pois.py` is idempotent. Preserves curated entries and user location-overrides (keyed by `osm_id`). Annual GitHub Action modelled on `update-michelin.yml`.

**Expected volumes.** ~3,500-4,500 new mooring entries, ~2,000 new waypoint entries across all 9 countries. NL densest.

**Acceptance criteria:**
- Every country shows visible markers when panned to.
- Toggling halte/port/lock layers works identically across countries.
- OSM markers visually distinct from curated; sidebar badge present.
- France behaviour unchanged.
- Re-running `fill_osm_pois.py` is idempotent.

## 5. Wave 3 — IENC for NL + DE

**Sources.**
- Netherlands: Rijkswaterstaat IENC download portal (annually-versioned ZIP cells, CC0).
- Germany: WSV ELWIS IENC portal (per-waterway ZIPs, free-with-attribution).

**Pipeline.** Reuse `extract_ienc.py`. It is S-57 generic — country-specific bits live in the input zips, not the code:

```bash
python3 extract_ienc.py \
  --zip ienc/FR.zip --zip "VNF Charts/..." \  # existing French zips
  --zip "ienc/NL_2026.zip" \
  --zip "ienc/DE_Rhein_2026.zip" --zip "ienc/DE_Mosel_2026.zip" --zip "ienc/DE_Main_2026.zip" \
  --out data/bridges.geojson \
  --out-channel-axis data/ienc_channel_axis.geojson \
  --out-obstructions data/ienc_obstructions.geojson \
  --out-locks data/ienc_locks.geojson \
  --out-moorings data/ienc_moorings.geojson \
  --reconcile french_canals_map.html
```

Cross-zip dedup-by-conservative-record logic already handles overlap.

**Risks / known unknowns.**
- IENC cells from different authorities use slightly different S-57 attribute encodings. May need targeted fixes in `extract_ienc.py` (small `if country == ...` branches). Tests extended with one fixture per new authority.
- File-size growth: `bridges.geojson` ~50 KB → ~150-200 KB; `ienc_channel_axis.geojson` ~1.2 MB → ~3 MB. Channel axis remains not-precached.
- Attribution block gets Rijkswaterstaat (CC0) + WSV (free-with-attribution) lines.

**Acceptance criteria:**
- Bridge clearance colouring works on NL/DE waterways with the vessel-profile filter.
- Channel axis renders where the OSM river deviates (notably Rhine meanders).
- French IENC behaviour byte-identical.

## 6. Wave 4 — Closures (FR + NL + DE + BE + AT)

Per-country adapters in a new module pattern. Each returns a normalised `Closure[]`:

```js
{ id, country, waterway, lat, lon, start, end, reason, severity, source_url }
```

| Country | API | Format | Notes |
|---|---|---|---|
| FR | VNF chômages | JSON | Reuse current `buildChomagesMarkers` fetch; normalise to shape |
| NL | RWS Stremmingen | REST JSON | New fetch + parse |
| DE | ELWIS RSS | XML per-waterway feed | New fetch + DOMParser |
| BE | DVW (Flanders) + SPW (Wallonia) | JSON / RSS | Two sub-adapters |
| AT | DoRIS Notice-to-Skippers | JSON | New fetch + parse |

**Caching.** Time-sensitive — never cached by the service worker. Adapters fetch on demand when the Closures layer is enabled. Per-country timeout; failures degrade silently with a "Closures unavailable — check <official URL>" footnote in the layer legend.

**UI.** Existing `chomagesGroup` renamed to `closuresGroup`. Country flag emoji prefixed to popup title (🇳🇱 🇩🇪 🇧🇪 🇦🇹 🇫🇷). Marker icon and popup body unchanged.

**For UK / IE / IT / CH / LU** — no closures fetch. Sidebar/legend shows a deep-link to the official portal pre-populated for the viewed area (CRT for UK, Waterways Ireland for IE, etc.).

**Acceptance criteria:**
- Toggling Closures layer shows current items from all 5 country feeds.
- Each popup has a working source-link.
- Failure of any single feed doesn't break the others.

## 7. Wave 5 — Constraints + routes

### Waterway constraints (hand-transcribed)

`waterway_constraints.json` extended with ~50 new entries from official authority publications, source cited inline:

```jsonc
{
  "Canal du Midi": { "air": 3.50, "draft": 1.60, "beam": 5.45, "length": 30, "source": "VNF" },
  "Rhine (Basel-Rotterdam)": { "air": 9.10, "draft": 2.50, "beam": 22.80, "length": 135, "source": "ZKR fairway specifications 2024" },
  "Standing Mast Route": { "air": null, "draft": 1.90, "beam": 4.50, "length": 17, "source": "Vaarwegen in Nederland 2024" }
}
```

`null` for air-draft on the Standing Mast Route is meaningful — that route is defined by unlimited air via opening bridges. The vessel-profile filter must treat `null` as "no upper bound for this dimension".

### Curated routes

~12-15 new entries in `routes.json` for the famous trips:
- Rhine (split into 3 routes by character: Basel → Strasbourg → Koblenz → Rotterdam)
- Moselle (Koblenz → Metz, connects to existing route 31)
- Main + Main-Donau-Kanal (Mainz → Nuremberg → Kelheim)
- Danube (Kelheim → Vienna)
- Standing Mast Route (NL)
- IJsselmeer crossings
- Belgian Albert Canal
- Caledonian Canal
- Shannon-Erne corridor
- Kennet & Avon + Thames
- River Po

Each gets `country`, `dist_km`, `locks`, `max_height`, `max_draught`, plus a new `description` field. As a side improvement, the existing French routes are backfilled with `description` (currently absent).

### Auto-derived routes

New script: `fill_auto_routes.py`. Walks `waterways.geojson`, groups contiguous LineStrings by normalised name, computes length and lock count from intersected `lock=yes` nodes. Emits one route per contiguous named waterway not already curated. Marked `source: 'osm'`.

### Route planner

- `ROUTE_CONNECTIONS` graph becomes dynamic. New helper `buildRouteConnections()` runs once at load: for each pair of routes, find geographic intersections via shared waypoints / lat-lon proximity in `waterways.geojson`. The hand-curated France connections move to a small override file that takes precedence.
- BFS pathfinding code unchanged.

**Acceptance criteria:**
- Route planner can route Auxerre → Amsterdam end-to-end.
- Vessel-profile filter colours every covered waterway by navigability.
- France routes still planable byte-identical to today (override file preserves them).
- A waterway with no constraint data still renders correctly in grey.

## 8. Cross-cutting concerns

**Edit Locations / overrides.** `french_canals_location_overrides_v1` keyed by waypoint/mooring `id`. OSM entries' IDs (`w_osm_<osm_id>`) are stable across re-syncs of `fill_osm_pois.py`. No migration needed; existing French overrides untouched.

**Google Places.** Already works EU-wide. No change.

**Michelin.** Remove the `', France'` filter from `fill_michelin.py`. Re-run the GitHub Action. Expected growth: 1,007 → ~3,500 entries. File-size impact: ~1 MB embedded in HTML.

**Tunnels & boat lifts.** `TUNNELS` migrated to `data/tunnels.json` and the data structure generalised: each entry gains a `kind: 'tunnel' | 'lift' | 'inclined_plane'` discriminator (existing 5 French entries become `kind: 'tunnel'`). Six new entries added: Strépy-Thieu (BE, lift), Ronquières (BE, inclined_plane), Anderton (UK, lift), Falkirk Wheel (UK, lift), Niederfinow (DE, lift), Henrichenburg (DE, lift). Booking, transit-time, and dimension limits per entry. Popup template branches on `kind` to render appropriate fields (convoys for tunnels, transit slots for lifts). The layer toggle and icon palette get a small refresh — "🛠 Structures" replaces "Tunnels" as the layer name.

**Tidal.** `TIDAL_DATA` migrated to `data/tidal.json`. New waterways (Thames, Zeeland, Scheldt, Severn) out of scope — the existing extension recipe in CLAUDE.md works as-is. Documented as future work.

**Live locks (Overpass).** Already EU-wide. No change.

**Weather (Open-Meteo).** Already EU-wide. No change.

**Attribution.** Footer in `index.html` gets new lines:
- Rijkswaterstaat (NL IENC) — CC0
- WSV / ELWIS (DE IENC) — free with attribution
- DVW / SPW (BE closures)
- DoRIS (AT closures) — viadonau
- All under existing OSM / Michelin / VNF credits.

## 9. Testing

- `tests/test_extract_ienc.py` extended with one fixture cell per new authority (NL + DE). Asserts same VERCLR aggregation and dedup behaviour.
- Manual smoke test per wave: pan to representative city in each new country, toggle each layer, verify markers render, verify popups show source-correct attribution.
- No automated UI tests planned. Project has none today; not introducing.

## 10. Rollout

Each wave is a separate PR / commit on `main`.

| Wave | Scope | Est. effort |
|------|-------|-------------|
| 1 | Rename + extract data + waterway overlay everywhere | ~1 day |
| 2 | OSM waypoints + moorings | ~1 day (script) + visual review |
| 3 | IENC NL + DE | ~half-day pipeline + ZIP downloads |
| 4 | Closures (4 adapters) | ~2 days |
| 5 | Constraints + routes (curated + auto-derived) | ~3 days |

Total ~7-8 working days.

---

## 11. Out of scope (explicit non-goals)

- Localisation / multi-language UI
- Vector tiles for waterways
- UK / IE IENC (doesn't exist — authorities don't publish S-57)
- IT / CH / LU closures (deep-link only)
- Tidal extensions (Thames, Zeeland, Scheldt) — separate future spec
- Per-country live water-level integrations (deep-links instead)
- Hand-curating non-French waypoints/moorings (deferred — `source: 'osm'` → `source: 'curated'` promotion happens organically over time)
- Renaming the GitHub repo or moving the live URL
